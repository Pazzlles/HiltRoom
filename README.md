# Приложение "Posts Explorer"

## ФИО
Курышева Александра Александровна

## Группа
Б9124-09.03.03пикд(з)

## Тесты

### Сколько сделано

- юнит-тестов: `11`
- интеграционных тестов: `4`

### Какие сценарии покрыты

- корректное начальное состояние `PostListViewModel`
- восстановление последнего успешного запроса при старте
- успешная загрузка списка
- ошибка загрузки списка
- `Retry` после ошибки списка
- пустой результат поиска даёт именно `Empty`, а не `Success(emptyList())`
- ошибка при пустом `postId` на detail-экране
- `Retry` после ошибки на detail-экране
- корректное преобразование `DTO -> model`
- отбрасывание невалидного `DTO` без `id`
- явная ошибка при `DTO` без `userId` для detail
- `Repository + Fake API + Room`: успешная загрузка и офлайн-чтение из `Room`
- `Repository + Fake API + Room`: новый успешный поиск заменяет старый кэш
- UI: ошибка -> `Retry` -> успешное состояние списка
- UI: список -> клик по элементу -> переход на detail именно для нужного `id`

В проекте не используются `Flow` / `StateFlow` / `SharedFlow` для экранного состояния, поэтому отдельное требование ДЗ №5 для `Flow` здесь не применяется.
